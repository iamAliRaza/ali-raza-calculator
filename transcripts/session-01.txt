⏺ Got it, Flutter web it is. You're right that F1 and D6 no longer apply. So
  does the HTML half of D7: Flutter's Text never interprets markup, though long
  names still need handling. F2 stands. We'll use plain TextFields and a strict

  "Infinity" and surrounding spaces.

  Switching to Flutter raises a few new points, which I've added to section F of
  the plan file:

  - F3. Exact maths. Dart's double has the same rounding errors as JavaScript,
    so we'll need the free rational or decimal package from pub.dev, or our own
    BigInt-based maths. Without that, 89.995 won't round to 90.00, and a result
    of exactly 89.17 could round up to 89.18.
  - F4. Testing in four browsers. Flutter can launch Chrome and Edge directly.
    Firefox and Safari need flutter run -d web-server (or a built build/web
    served locally) opened by hand. The README should explain this and pin the
    Flutter version.
  - F5. Renderer. I'd use the default build rather than --wasm, for the widest
    browser support. Also, by default the app downloads part of Flutter's
    rendering engine from Google on first load, so it needs internet then.
    Building with --no-web-resources-cdn avoids that if you want it to work
    fully offline.
  - F6. Accessibility. Flutter web turns screen-reader support off until the
    user enables it. So the D8 announcements and the C2 error highlighting need
    explicit Semantics work.
  - F7. Testability. Giving the results area, field errors and target letter
    Keys means most acceptance criteria can be checked with flutter test,

  Parser
  - Trim the text with Dart's trim(), which also removes tabs and non-breaking
    spaces. If nothing is left, the field is blank.
  - Otherwise the text must match ^[+-]?(\d+\.?\d*|\.\d+)$. In Dart, \d matches
    only the digits 0–9, so anything else gives NotANumber.
  - Count the digits after the point as typed. More than 2 gives
    TooManyDecimals.
  - Before handing the text to Decimal.parse, I tidy it so the package never
    sees unusual forms like "+5", ".5" or "5.". I won't rely on how
    Decimal.parse treats them.

  Validation
  - A row is in use if any field is non-blank.
  - Each field shows its first failure only, in this order:
    a. parse problems
    b. too many decimals
    c. range
    d. the "more than max points" check, which is skipped when Max points itself
       is invalid
  - Blank-field rules: a row in use needs a Weight. Max points is needed once
    Points earned is filled.
  - Target gets the same checks but always shows its one message.

  Maths
  - All calculations are done in Decimal or Rational from the decimal package.
    Dividing two Decimals gives an exact Rational.
  - W is the total weight. S is the marked weights' share: each marked row's
    weight × points earned ÷ max points, added up.
  - Grade: S divided by the marked weights' total, × 100.
  - "At least" grade: S ÷ W × 100.
  - Highest reachable grade: (S + the unmarked weights' total) ÷ W × 100.
  - Required score: (target × W ÷ 100 − S) ÷ the unmarked weights' total × 100.
  - Decisions, all made on exact values:
    - required score ≤ 0 → "Already secured"
    - required score > 100 → "Not achievable"
    - weights total exactly 100 → required score shown at all
  - Final grade: shown only when every row in use is marked and the weights
    total exactly 100.
  - Coverage line: the marked weights' total. This works because the line only
    shows when the weights total 100.

  Rounding and display
  - Multiply the exact value by 100, then:
    - round half up for grades;
    - round up for the required score;
    - round down for the "at least" and highest reachable grades.
  - Format with 2 decimals. I'll put in the thousands separators myself rather
    than add the intl package.
  - The letter is worked out from the rounded number.

  evaluate
  - Builds the results area following the spec's four-step results order: field
    errors, then weights, then grade, then required score.
  - Add and Remove are based on the number of rows on screen (B12).
  - It handles 0 rows or more than 20 without throwing.

  Order of work:
  1. Parser
  2. Validation (gets S-3 passing)
  3. Maths and formatting (S-2, S-4, S-6)
  4. Required score (S-5)
  5. S-1 and S-7 should then pass as well
